## ✨ 功能特性

### 🎯 核心功能

- **统一身份认证直登**
    - 🔐 直接输入北理统一身份认证账号和密码，无需配置抓包代理或复制登录请求
    - 📱 如系统要求短信验证，可在页面中直接提交验证码
    - 🔄 自动完成班车授权回调并保存班车用户标识
    - ⚡ 班车 API 的 `apitoken` 和 `apitime` 按请求自动生成，无需手动维护

- **智能抢票**
    - ⚡ 自动在发车前 1 小时开始抢票
    - 🎲 支持手动选座和自动抢座两种模式
    - 🔄 自动轮询座位，直到抢到目标数量
    - 📊 支持座位优先级设置（高/中/低）

- **座位管理**
    - 🗺️ 可视化座位布局（真实巴士布局）
    - 👆 左键点击选座，右键设置优先级
    - 🎨 直观的座位状态显示（可选/已订/禁用）
    - 📈 批量设置座位优先级

- **任务管理**
    - 📝 任务列表实时更新
    - 🔍 任务状态追踪（准备中/等待开抢/抢票中/成功/失败）
    - ⏸️ 支持取消和删除任务
    - 📊 显示抢票进度和已抢座位

### 📢 通知系统

- **邮箱通知**
    - 📧 支持 SMTP 邮件发送
    - 🎨 HTML 格式邮件模板
    - ⚙️ 自定义 SMTP 服务器配置

- **企业微信通知**
    - 💬 企业微信群机器人
    - 📱 Markdown 格式消息
    - ⚡ 实时推送抢票结果

### 🛡️ 安全特性

- 🔐 配置信息本地存储
- 🔒 敏感信息脱敏显示
- ⚠️ 完善的错误处理机制
- 🚨 异常自动恢复

## 🚀 快速开始

### 环境要求

- Python 3.10 或更高版本
- pip 包管理器
- 稳定的网络连接

### 安装步骤

1. **克隆项目**

```bash
git clone https://github.com/vc6-1998/BITBusGrab.git
cd BITBusGrab
```

2. **安装依赖**

```bash
pip install -r requirements.txt
```

3. **运行应用**

```bash
python app.py
```

4. **访问系统**

   打开浏览器访问：`http://localhost:23200`

### 统一身份认证登录

1. 启动程序，在运行程序的电脑上打开 `http://localhost:23200`。
2. 点击右上角 **设置**，进入 **API 配置**，输入北理统一身份认证账号和密码，然后点击 **使用统一身份认证登录**。
3. 如果统一身份认证要求短信验证，在页面输入绑定手机收到的验证码并提交。
4. 页面显示 **已登录班车服务** 后，即可查询班车和创建抢票任务。

登录过程会自动完成统一身份认证和班车服务授权回调，不需要先在钉钉中捕获登录请求，也不需要安装或配置抓包代理、手动复制 API 请求头。`apitoken` 和 `apitime` 会按班车网页使用的算法在每次请求时生成。

账号密码、短信验证码和 SSO Cookie 不会写入配置文件；本地仅保存班车服务返回的用户标识。登录页面通过本机回环地址连接程序，程序再通过 HTTPS 与 `sso.bit.edu.cn` 通信；网页服务只监听 `127.0.0.1`，请从运行程序的这台电脑访问。

短信验证仅在统一身份认证要求时出现。若遇到图形验证码风控，当前版本会提示该验证暂不支持。

## 📖 使用指南

### 基本操作

#### 1. 配置系统

首次使用只需登录北理统一身份认证，不需要单独配置班车 API 凭证：

1. 点击右上角 **设置** 按钮
2. 在 **API 配置** 标签页输入统一身份认证账号和密码并登录
3. 如页面要求短信验证，输入收到的验证码完成登录
4. 通知方式可在 **通知配置** 标签页单独保存

#### 2. 查询班车

1. 选择 **线路方向**（如：良乡校区 → 中关村校区）
2. 选择 **日期**
3. 点击 **查询** 按钮
4. 查看可用班车列表

#### 3. 选择座位

1. 点击班车卡片上的 **选座** 按钮
2. 查看座位布局和可用座位
3. 左键点击选择座位
4. 点击 **确认抢票** 创建任务

### 座位优先级设置

#### 为什么需要优先级？

在自动抢票模式下，系统会按照优先级顺序尝试抢座，优先抢占高优先级座位。

#### 如何设置优先级？

**方法一：单个设置**

1. 右键点击任意座位
2. 在弹出菜单中选择优先级（高/中/低）
3. 座位上会显示优先级标识（H=高，L=低）

**方法二：批量设置**

1. 点击批量设置按钮
2. 选择 **全部高优先级** / **全部中优先级** / **全部低优先级**

**注意事项：**

- 默认所有座位为中优先级
- 已被预订的座位也可以设置优先级（用于候补）
- 优先级配置会保存在浏览器本地

### 自动抢票模式

#### 开启自动模式

1. 在选座页面勾选 **自动抢票模式**
2. 设置 **目标座位数量**（1-10 个）
3. 系统会按优先级自动抢座

#### 工作原理

```
开始抢票
    ↓
获取当前座位状态
    ↓
筛选可用座位
    ↓
按优先级排序
    ↓
尝试预订优先级最高的座位
    ↓
成功？
├─ 是 → 已抢座位数 +1 → 达到目标数量？
│                      ├─ 是 → 完成
│                      └─ 否 → 继续抢票
└─ 否 → 标记该座位为已尝试 → 继续抢票
```

### 通知配置

#### 邮箱通知

1. 在设置中切换到 **通知配置** 标签
2. 勾选 **启用邮箱通知**
3. 填写邮箱配置：
    - **SMTP 服务器**：如 `smtp.qq.com`
    - **端口**：通常为 `465`（SSL）或 `587`（TLS）
    - **发件邮箱**：您的邮箱地址
    - **授权码**：邮箱的 SMTP 授权码（非登录密码）
    - **收件邮箱**：接收通知的邮箱

**获取 QQ 邮箱授权码：**

1. 登录 QQ 邮箱
2. 设置 → 账户 → POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务
3. 开启 SMTP 服务
4. 生成授权码

#### 企业微信通知

1. 勾选 **启用企业微信通知**
2. 填写 **Webhook URL**

**获取 Webhook URL：**

1. 在企业微信群中添加群机器人
2. 复制机器人的 Webhook 地址
3. 粘贴到配置中

## ⚙️ 配置说明

### config.json 文件结构

```json
{
  "API_HOST": "hqapp1.bit.edu.cn",
  "USER_ID": "由登录流程写入",
  "notification_methods": [
    "email",
    "wechat_work"
  ],
  "email_config": {
    "smtp_server": "smtp.qq.com",
    "smtp_port": "465",
    "sender_email": "your@email.com",
    "sender_password": "your-smtp-auth-code",
    "receiver_email": "receiver@email.com"
  },
  "wechat_config": {
    "webhook_url": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=..."
  }
}
```

### 座位优先级配置

优先级配置保存在 `seat_priorities.json` 中：

```javascript
{
    "3"
:
    1,   // 3 号座位：高优先级
        "4"
:
    2,   // 4 号座位：中优先级
        "5"
:
    3,   // 5 号座位：低优先级
    // ... 其他座位
}
```

## 📡 API 文档

### 后端 API 端点

#### 车辆查询

```http
POST /api/search
Content-Type: application/json

{
  "origin": "良乡校区",
  "destination": "中关村校区",
  "date": "2025-01-15"
}
```

#### 获取座位信息

```http
GET /api/seats/:bus_id?date=2025-01-15
```

#### 创建抢票任务

```http
POST /api/reserve
Content-Type: application/json

{
  "bus_id": "123456",
  "bus_info": {
    "origin_address": "良乡校区",
    "end_address": "中关村校区",
    "origin_time": "08:00",
    "date": "2025-01-15"
  },
  "seat_ids": [5, 6, 7],
  "auto_mode": true,
  "target_count": 2,
  "seat_priorities": {
    "5": 1,
    "6": 2,
    "7": 3
  }
}
```

#### 获取任务列表

```http
GET /api/tasks
```

#### 取消/删除任务

```http
POST /api/tasks/:task_id/cancel
DELETE /api/tasks/:task_id
```

#### 配置管理

```http
GET /api/config
POST /api/config
```

## ❓ 常见问题

### Q1: 登录失效怎么办？

**A:** 在设置中退出登录后重新使用北理统一身份认证登录。班车请求令牌会自动生成，不需要手工更新 Token 或 Time。

### Q2: 为什么抢票失败？

**可能原因：**

- ❌ 班车登录状态已失效
- ❌ 座位已被他人抢占
- ❌ 网络连接不稳定
- ❌ 系统维护中

**解决方案：**

1. 在设置中重新登录北理统一身份认证
2. 设置更多候补座位
3. 使用自动模式提高成功率

### Q3: 如何提高抢票成功率？

**建议：**

1. ✅ 使用自动抢票模式
2. ✅ 设置合理的座位优先级
3. ✅ 目标座位数设置为 1-2 个
4. ✅ 提前创建任务（系统会自动在合适时间开抢）
5. ✅ 候补已预订座位

### Q4: 邮箱通知发送失败？

**检查项：**

- ✅ SMTP 服务器地址是否正确
- ✅ 端口是否正确（QQ 邮箱用 465）
- ✅ 是否使用授权码而非登录密码
- ✅ 是否开启了 SMTP 服务

### Q5: 座位编号对应关系？

巴士座位布局（共 51 个座位）：

```
前方 →

[1]        [2]      (驾驶位旁，系统保留)
[3][4]   [5][6]
[7][8]   [9][10]
... (中间座位)
[47][48][49][50][51]  (最后一排)

← 后方
```

- 1、2 号：系统保留（司机旁）
- 49 号：系统保留
- 其他座位可选

### Q6: 可以同时抢多个时段的车吗？

**A:** 可以！系统支持创建多个抢票任务，每个任务独立运行。

### Q7: 配置会丢失吗？

**A:**

- API 配置保存在服务器 `config.json` 文件中，不会丢失
- 座位优先级保存在 `seat_priorities.json` 文件中，不会丢失
